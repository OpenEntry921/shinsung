# 운영 절차

## 명부

1. 명부 이용 목적·처리 주체·이용 근거·보유기간을 확정한다. 이 사이트는 교회 공식 승인 여부를 임의로 주장하지 않는다.
2. `roster` 권한 관리자가 `/admin` → 교인 명부에서 XLSX 업로드한다. 파일은 서버 요청 처리 중에만 열며 원본을 보관하지 않는다. 확인 대기 데이터는 암호화한 30분 만료 미리보기로 저장한다.
3. 누락·중복·동명이인·공용 번호·0 복구 후보·기존 기록 대비 변경·누락을 확인한다. 불확실한 번호는 직접 수정한다. 중복 행은 하나만 반영한다.
4. 기존 이름·번호 일치는 기본 기존 ID 유지. 변경은 **별도 신원 확인 후 기존 교인 ID 연결**. 확인 없이 신규 등록으로 처리하면 과거 글과 연결이 끊길 수 있으므로 생성 여부를 판단한다.
5. 새 교인은 신규 등록을 선택하고 확인 후 반영한다. 누락은 자동 삭제·비활성화하지 않는다. 별도 활성 상태 조치에는 사유를 남긴다.
6. 번호 또는 이름 변경 시 기존 세션·인증번호를 폐기한다. 이전 ID 및 글 연결을 보존한다. 비활성 교인은 기존 세션이 있어도 접근할 수 없다.
7. 공용 번호는 일반 SMS 로그인을 막는다. 본인 신원 확인 후 특정 ID에 대한 일회성 접속 정보만 발급한다. 식별번호와 인증번호를 확인한 본인에게만 전달한다. 15분 만료·1회 사용이며 공용 비밀번호가 아니다.

일반 교인에게는 명부 검색·조회·내보내기 API가 없다. 동명이인 작성자는 전화번호 대신 비민감한 내부 ID 일부로 구분한다.

## 사건과 조문

1. `content` 관리자 사건 초안을 작성한다. 발생일·문서 작성일·결정일을 구분한다.
2. 확인된 사실, 당사자별 주장·반론, 미확인 사항, 출처·해당 부분, 검토 쟁점, 운영진 의견·근거, 공식 판단 기관·사건번호·결정일·범위·확정 여부를 별도 항목에 기록한다.
3. 조문은 통합 총회 공식 원문과 개정 공고를 직접 확인한다. 헌법/시행규정, 편·장·조·항, 개정/시행/확인일, 사건 당시 적용 기간을 기록한다. 합동 조문을 혼용하거나 현재 조문을 소급 적용하지 않는다.
4. 작성자 외 `publish` 검토자가 실제 출처와 적용 여부를 확인하고 조문을 검증한다. URL 제한은 공식 도메인을 제한할 뿐 원문 일치·적용 판단을 자동 보장하지 않는다. 검증 전 교인 화면은 정확한 조문 대신 확인 중으로 표시한다.
5. 사건을 검토 중으로 전환하고 다른 승인자가 근거를 남겨 게시한다. 같은 관리자 셀프 게시를 막는다. 조문 미검증이면 그 부분만 확인 중이며 사건 전체 자동 판정은 없다.
6. 사건 수정 시 기존 게시 상태를 초안으로 되돌리고 별도 재검토·재게시한다. 이전 상세 버전은 제한 관리자만 조회한다. 교인에게는 현재 공개 버전과 게시·정정 근거만 보여준다.
7. 당사자 양측에 동일한 자료 제출·답변·정정 기회를 부여한다. 한쪽 미응답을 잘못 인정으로 표시하지 않는다. 검토의 중립성은 편집 절차와 실제 근거를 통해 유지해야 하며 소프트웨어가 보장하지 않는다.

## 자료와 가림

1. 자료 제목·출처·확보일·원문/발췌 여부·범위·가림 이유를 기록한다.
2. 원본은 관리자 전용으로 업로드한다. 교인 열람본은 원본과 별도 파일로 만든다.
3. 불필요한 연락처·주소·서명·계좌·상담 내용을 외부 도구에서 제거한다. 검은 사각형을 덧씌우는 것만으로 처리하지 않는다. PDF는 실제 redaction 적용 또는 안전한 래스터 재생성 후 OCR/숨겨진 레이어·메타데이터·첨부 객체를 포함해 점검한다.
4. 작성자 외 승인자가 전체 내용을 확인하고 텍스트 추출·복사·레이어·객체 검사를 통해 가린 부분이 복구되지 않는지 검증한다. 검증 체크박스는 수동 검토의 기록이며 PDF 자동 가림 기능이 아니다.
5. 승인된 열람본만 게시된 사건에서 다운로드할 수 있다. 공개 폴더·영구 공개 URL을 만들지 않는다. 원본 다운로드는 content/publish 관리자만 가능하다.
6. 문제가 발견되면 승인자가 사유를 남겨 열람 철회한다. 사이트 내에서 원본 파일을 덮어쓰지 않는다. 교체 파일은 새 자료로 등록하고 구 열람본 승인을 철회한다.

PDF/PNG/JPEG만 최대 요청 8MB로 업로드한다. 파일 헤더·크기·권한을 검사하고 강제 다운로드로 제공한다. **전문 악성코드 검사·PDF 재작성 엔진은 미연결**이다. 관리자 확보 자료도 의심 파일은 별도 검사 후 등록한다.

## 게시판과 정정

- 서버가 활성 세션의 ID와 명부 실명을 사용한다. 전화번호를 공개하지 않는다. 작성자는 자신의 글만 수정·삭제하며 수정 표시가 남는다.
- 관리자에게 본문 수정 API는 없다. 욕설·위협·개인정보 노출·반복 도배 등 공개 기준에 따른 비공개·복구만 가능하고 사유를 기록한다.
- 본인은 내 글·관리 조치 확인에서 비공개 글과 사유를 읽고 이의를 제기한다. 반대 의견·비판 자체를 삭제 이유로 삼지 않는다.
- 신고·정정·자료 제안·이의 제기는 비공개 요청으로 접수한다. 파일 제출은 운영자에게 안전한 별도 경로를 문의한다. 운영자는 양측에 같은 기준으로 답변하고 처리 결과를 작성자에게 제공한다.
- 삭제 글과 글 과거 버전 30일, 관리 이력 90일, 완료 요청 180일 뒤 정리한다. 영구 명부·원본·사건 변경 이력·백업 보존은 확정한 정책에 따라 담당자가 별도 정리한다.
- 이미 캡처·전달된 자료를 시스템이 회수할 수 있다고 약속하지 않는다.

## 장애·복구

- SMS 미설정·실패·대입 제한이면 관리자에게 연락하도록 안내한다. 실패한 발송에서 인증을 성공 처리하지 않는다. 업체가 접수해도 실제 도착은 별도 확인해야 한다.
- DB/자료는 `/data` 영구 볼륨에 둔다. 서비스 복제본 1개로 운영한다.
- 일일 암호화 백업과 별도 장소 보관, 정기 복구 훈련을 예약한다. 키를 함께 저장하지 않는다.
- 세션 만료: 교인 2시간, 관리자 30분. 관리자 퇴임 시 CLI로 비활성화하여 세션 폐기한다.
- APP_SECRET 또는 DATA_KEY 변경은 단순 재배포 작업이 아니다. 기존 조회키/암호화 자료 이관을 수행하는 별도 유지보수 절차가 필요하다.
