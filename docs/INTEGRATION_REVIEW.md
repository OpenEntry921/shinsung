# 타임라인·상황판·확인 절차 검토

기존 체크아웃을 사용한다. 추가 Git worktree를 만들지 않는다. 운영 DB나 실제 명부로 테스트하지 않는다.

## 개발

Python 3.12에서 `sh scripts/install.sh`로 고정된 requirements를 설치한다. `APP_MODE=development .venv/bin/python manage.py collectstatic --noinput` 후 `APP_MODE=development .venv/bin/python manage.py test`와 `.venv/bin/python scripts/verify_backup.py`를 실행한다. `APP_MODE=development .venv/bin/python manage.py runserver 127.0.0.1:8000 --noreload`로 시작한다. 상태 검사는 `/health/`의 JSON과 비로그인 `/cases/material/E01/`의 로그인 리다이렉트로 확인한다. 개발 모드는 실제 운영에 사용하지 않는다.

시작 스크립트는 샘플 교인을 자동 생성하지 않는다. 필요한 화면 검증에는 격리된 임시 DB와 테스트 전용 가상 데이터만 사용한다. 개발 DB에도 기존 교인이 자동 승인되지 않는다. 관리자 계정은 별도로 생성하며, 일반 브라우저 로그인에는 기존 관리자 TOTP 추가 인증이 필요하다.

## 운영 전 필수 설정

- `OPERATOR_NAME`, `OPERATOR_CONTACT`: 실제 운영 주체와 철회·정정 문의 창구.
- `APPLICATION_RETENTION`: 수집·이용 정보의 구체적 보유기간과 파기 기준.
- `CHURCH_RECIPIENT`, `CHURCH_CONTACT`, `CHURCH_RETENTION`: 실제 수신 기관·창구와 구체적인 수신자 보유·파기 기준. 모두 설정되기 전 가입 접수는 차단된다. 값을 가상으로 채우지 않는다.
- `APP_MODE=production`, 강한 `DJANGO_SECRET_KEY`, `ALLOWED_HOSTS`, HTTPS/CSRF 설정, 관리자별 `ADMIN_MFA_SECRETS` 유지.
- 개인정보 관련 고지 내용이 바뀌면 `portal/access.py`의 동의 문안 버전을 올리고 재동의를 받는다. 보유·파기 운영은 고지한 기간에 맞춰 관리자 절차로 수행한다. 신청 정보의 자동 파기 작업은 포함하지 않는다.

신청은 새 교인 생성·기존 교인 자동 연결·접근 권한 부여를 하지 않는다. 관리자가 신청별 동의 고지를 확인하고 기존 교인 ID를 수동 연결한다. 교회 수동 대조 요청 시각·회신, 교인 대조 방법·결과, 별도 본인 확인 방법·시각을 관리자 전용으로 남긴다. 이름·번호 일치는 본인 확인 근거가 아니다. 실제 확인 후 승인한다. 승인 상태 변경은 관리자 이력과 안전한 이전 상태를 남기고 세션 버전을 갱신한다. 승인·동의 철회 또는 비활성화는 다음 요청부터 기존 세션을 차단한다. 외부 전송 기능은 없다.

상황판은 공개 가능한 내용만 등록하고 개인정보 제거를 확인해 게시한다. 수신 주체·실제 전달일 없는 '전달 완료'는 검증 오류다. 답변 요청일은 규정상 기한이 아니다. 실제 자료 없이는 진행 기록과 로드맵 상태를 등록하지 않는다. 관리자 변경 이력은 비공개이며 원문·상담 기록을 상황판에 입력하지 않는다.

## 마이그레이션·백업·영구 저장소

추가 모델만 생성하며 기존 교인·게시글·요청·사건·댓글 ID와 관계를 수정하지 않는다. E01~E30과 `reading_key`를 유지한다. 기존 사건 HTML의 각 article 본문을 그대로 보존하고 서버에서 선택한 사건 하나만 출력한다. 공개 저장소에 기존 사건 텍스트가 이미 존재한다. 본 개편은 이를 비공개로 만들지 않으며 새 비공개 자료를 커밋하지 않는다.

운영 반영 전 서버 쓰기를 중지하고 `backup_private`로 저장소 밖에 백업한다. 암호화된 외부 비공개 저장소에 보관한 뒤 빈 별도 DATA_DIR에 `restore_private`로 복구하고 ID·관계·파일과 무결성을 확인한다. 복구는 기존 세션·인증 수단을 무효화한다. `scripts/verify_backup.py`는 가상 데이터로 이를 검사한다. 현재 개발 환경의 통과는 실제 운영 외부 백업 완료를 뜻하지 않는다.

`DATA_DIR` 문자열 설정만으로 영구 디스크가 연결되지 않는다. 실제 Cloudtype 영구 볼륨 경로·마운트와 재시작 후 동일 DB·비공개 파일 보존을 운영자가 확인해야 한다. 이 작업은 호스팅·배포·마이그레이션 운영 실행을 하지 않는다.

## 검토 범위와 제한

첫 화면은 목적 안내 → 공동 상황판 → 로드맵 → 메타데이터 타임라인 → 정책 연결이다. 27개 표시 순서와 불확실 E06·E10·E22의 별도 묶음을 유지한다. 이전·다음은 표시 순서이며 확정 연대순을 의미하지 않는다. 기존 숫자 사건 주소와 게시판 연결은 상세 주소로 연결하며 이전 fragment 북마크는 자체 정적 스크립트로 해석한다. 의견 ID 해석도 인증 뒤 수행한다.

머지·Cloudtype 배포·개인정보 전송은 별도 실행하지 않는다. 새 비공개 자료·DB·댓글·신청 정보·백업·인증값은 Git 대상에 포함하지 않는다. 화면 캡처는 저장소 밖의 검토 산출물이다. 정책 문구만으로 법적 위험이 해소된다고 판단하지 않는다.
