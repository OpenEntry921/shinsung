# 사건별 실명 의견 운영과 검증

## 이번 변경

사건 HTML 본문은 DB로 옮기지 않습니다. E01~E30의 원래 본문 문단·순서·날짜·불확실성·기존 네 영역은 유지하고, 네 번째 영역의 제목과 작성 주체를 구분한 뒤 다섯 번째 토론 영역을 덧붙입니다. 사이트 제목과 참여 안내를 변경합니다. 과거 문서의 반론·진행 상황 미반영 안내는 기존 문서 기준의 설명으로 남고, 새로 접수·검토된 반론은 별도 영역으로 구분합니다.

`reading_registry.py`가 사건번호의 단일 목록입니다. `0010_member_discussions`는 새 댓글 테이블과 게시글·요청의 선택 연결 필드만 추가합니다. 기존 `Case`, 교인·게시글·문서의 ID와 외래키를 변경하거나 초기화하지 않습니다. 댓글은 한 번의 조회로 묶어 표시하고, 공개 승인된 반론 발췌도 별도로 한 번 조회합니다.

## 접속과 작성

- 기존 이름·전화번호 로그인: 열람 가능, 본인 확인 완료 아님.
- 의견 작성·수정·삭제: 명부 관리자가 기존 관리자 추가 인증 및 별도 신원 확인을 마친 후 `/exception-issue/`에서 발급한 개인별 일회용 접속 수단을 `/exception/`에서 사용. 발급 유효기간 15분, 1회만 사용 가능. 확인된 교인·명부 버전·만료 시각을 서버 세션에 기록하며 최대 1시간 유지.
- 과거 명부 세션과 확인 표식 없는 과거 예외 세션은 자동 승격하지 않음. 관리자 열람 권한은 교인 명의 작성 권한이 아님.
- 새 SMS나 외부 서비스는 필요 없음. 개발 모드 예외 발급은 기존대로 가상 교인만 허용.

댓글·답글은 서버가 작성 교인·등록 실명·비민감 구분 표기를 지정합니다. 한 단계 답글만 허용하며 다른 사건 부모 연결, 작성자 위조, 타인 수정·삭제를 거부합니다. 입력 오류·횟수 제한 시 내용을 보존하고 원래 사건 위치에서 오류를 표시합니다.

신고·정정·비공개 반론은 사건번호와 의견을 미리 연결한 기존 요청 화면으로 받습니다. 요청 원문과 처리 답변은 본인과 권한 있는 관리자만 봅니다. 실제 접수된 반론의 공개용 발췌를 만들고 개인정보·표현을 검토한 뒤 명시적으로 승인한 경우에만 사건 네 번째 영역에 표시합니다. 빈 자료를 임의로 채우지 않습니다.

관리자는 의견을 대신 고쳐 쓸 수 없고 숨김·복원과 사유 기록만 가능합니다. 공개 사유는 정해진 분류로만 표시합니다. 수정 전 내용과 관리자 조치 이력은 관리자 전용입니다. 반대 의견 자체는 조치 사유가 아닙니다. 삭제 의견 본문은 30일, 이력은 90일 기준으로 `purge_private`가 정리합니다. 법적 보존 예외는 기존 운영 정책으로 별도 고지해야 합니다.

## 로컬 검증

가상 교인·가상 의견만 사용합니다. 실제 사건 본문을 테스트 fixture나 결과 로그에 복사하지 않습니다.

```sh
APP_MODE=development python manage.py test --noinput
APP_MODE=development python manage.py check
APP_MODE=development python manage.py makemigrations --check --dry-run
python scripts/verify_backup.py
```

2026-10-18 로컬 확인:

- 전체 테스트 106개 통과. 기존 본문 보존·접근 통제 검증을 유지하고, 기존 사건 테이블 조회 금지 검사는 정확한 테이블명으로 검사하여 새 댓글 테이블과 구분.
- 기존 HTML의 모든 본문 문단을 main과 대조하여 동일함을 확인. 30개 ID·순서·불확실 날짜 별도 구분 유지. 네 영역 120개, 토론 30개.
- 사건·조문·문서 DB 0건, 외부 본문 파일 없이 첫 진입 시 전체 본문 표시.
- 위조·다른 사건 답글·답글의 답글·타인 수정/삭제·미확인 세션·비활성·미인증·CSRF 차단, 출력 이스케이프, 비공개 요청과 수정 이력 보호.
- 추가 마이그레이션 전후 가상 교인·사건·게시글·요청 ID/외래키 보존.
- 가상 DB 백업·체크섬·복구 후 댓글·답글·요청·이력·교인/게시글 연결 유지. 비어 있지 않은 복구 대상과 손상된 백업은 거부. 복구 시 과거 세션 무효화.
- Chromium, 운영 모드 로컬 서버, 1280px PC/390px 모바일에서 명부 열람→개인별 접속 확인→의견·답글·수정·삭제, 오류 입력 보존, 전체 세로 순서·가로 넘침/본문 내부 스크롤 없음, 로그아웃 확인. 캡처는 비공개 작업 경로에만 보관.
- 로컬 동일 SQLite 경로로 새 worker를 시작한 뒤 가상 댓글·답글·수정 이력 보존 확인.

## 운영 전 남은 확인

이 작업에서 Cloudtype 배포·재시작·DB 이관은 하지 않습니다. 전달받은 현재 서비스에는 영구 디스크가 없으며 `/data/portal.sqlite3`의 재배포 보존을 확인하지 못했습니다. `DATA_DIR` 설정만으로 보존되지 않습니다. 실제 외부 백업 반출·체크섬·복구 가능성과 제공업체의 저장 보존 조건을 확인하기 전에는 운영 보존 완료라고 판단하지 마세요.

사용자가 별도로 검토·머지·배포할 때는 먼저 실제 외부 백업과 보존 가능한 운영 저장 환경을 확보합니다. 기존 시작 절차의 마이그레이션·역할 초기화를 유지합니다. 명부 관리자·게시판 관리자 계정과 기존 관리자 TOTP 설정을 확인해야 개인별 접속 발급과 의견 조치를 사용할 수 있습니다. 새 환경변수·유료 서비스·포트 변경은 추가하지 않습니다.

실제 본문 변경을 원격 제출하기 직전에 GitHub 비공개 여부를 확인합니다. 공개 상태에서는 본문이 포함된 변경을 푸시하지 않습니다. 로그인 제한은 공개 저장소 소스의 비공개화를 대신하지 않습니다.
