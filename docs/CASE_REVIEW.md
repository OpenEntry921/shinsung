# 사건 자료 등록·검토·게시

## 이번 구현과 실제 자료의 상태

화면·데이터 모델·관리자 검토 경로는 구현했지만, 이 작업에는 내부 메모 파일 자체가 전달되지 않았습니다. 원문을 확인한 사건 초안은 0건이며, 실제 사건·문서·확정 조문·판결 내용을 등록하거나 게시하지 않았습니다. 아래 주제 목록은 사용자가 지정한 검토 범위에 따른 원자료 체크리스트이며 첨부 문서에서 추출한 사실 목록이 아닙니다. 실제 원문을 확보한 뒤 보호된 별도 운영 환경에서 관리자가 가져오기를 실행해야 합니다.

개발 모드는 가상 교인으로 세 영역 구조와 빈 상태만 검증합니다. 실제 DOCX/PDF 업로드와 메모 추출·사건 초안 전환은 개발 모드에서 차단됩니다. `seed_demo`에는 자료를 추가하지 않습니다.

## 운영 전 인증·저장소 설정

운영 환경은 `APP_MODE=production`이어야 합니다. 실제 SMS 연결, HTTPS, 충분한 서버 비밀키, 각 관리자의 개인별 TOTP, 비공개 영구 `DATA_DIR`와 백업·복구를 먼저 검증합니다. `DATA_DIR`는 체크아웃 밖의 영구 디스크여야 합니다. `/data` 등 영구 디스크의 소유권과 UID 10001의 권한을 확인하고 공개 정적 파일 경로와 연결하지 마세요.

실제 인증 및 비공개 영구 저장소를 운영자가 확인한 뒤에만 `PRIVATE_STORAGE_CONFIRMED=true`, `REAL_MATERIALS_ENABLED=true`를 설정합니다. 이 변수는 운영자의 확인을 기록하는 게이트이며 디스크의 영속성이나 SMS 실제 발송을 자동 검증하거나 보증하지 않습니다. 값을 입력했다고 운영 준비가 완료되는 것이 아닙니다. 누락·잘못된 APP_MODE 값은 실제 자료 등록을 허용하지 않습니다. SMS 설정이 없으면 실제 자료 가져오기도 거부합니다.

## 관리자 등록 순서

1. 내용 편집자에게 사건·설명·근거·조문·결정·가져오기 후보 편집 권한을 부여하고, 별도 게시 승인자에게 게시 권한을 부여합니다. 일반 교인은 이 관리자 기능에 접근하지 못합니다. 관리자 로그인 후 TOTP 추가 인증이 필요합니다. `bootstrap_roles`는 새 모델의 운영 역할을 초기화합니다.
2. 관리자 **Document** 화면에서 출처·확보일·작성일·송달일·결정일·원문/발췌 및 범위를 입력합니다. 내부 검토용 DOCX는 **내부 검토 메모**로 지정합니다. 원본은 비공개 저장소에 보관하며 원래 파일명 대신 임의 ID로 저장합니다. 메모는 열람본·게시 상태·원자료 직접 확인을 지정할 수 없습니다.
3. `/materials/import/`에서 해당 DOCX를 선택해 후보를 추출합니다. 문단과 표 행을 처리하며 같은 주제의 경과를 묶습니다. 식별 가능한 사건번호는 서로 다른 묶음으로 남깁니다. 동일 파일의 SHA256와 후보 키를 이용해 반복 추출 시 기존 묶음을 반환합니다.
4. 후보의 내부 발췌·출처 위치·날짜 후보·필요 원자료·조문 번호 후보를 관리자만 확인합니다. 메모 기준일은 2026-09-19입니다. 전략 문구·전략 제목의 절은 보수적으로 제외하고, 분류되지 않은 블록 수를 표시합니다. 규칙 기반 추출은 완전한 문서 해석이 아니므로 누락·잘못된 묶음·별도 사건번호·표 머리글과 각 행의 관계를 원문과 대조하세요. 누락 내용은 관리자에서 별도 사건 초안으로 작성합니다.
5. 후보 편집 화면에서 사실과 의견을 분리한 **중립 요약**, 중립 제목과 날짜 정확도를 작성합니다. 금액·날짜·인명 차이는 검토 대상으로 남깁니다. 전략·개인정보 제외 검토를 확인한 후 **사건 초안으로 등록**합니다. 내부 발췌 전체는 사건 본문에 자동 복사하지 않습니다. 메모 내용은 미확인 사항으로만 등록하고 조문 본문이나 공식 결정을 만들지 않습니다. 동일 후보를 반복 전환해도 기존 사건 ID를 유지합니다. 다른 파일 버전의 비슷한 후보는 기존 사건과 수동 대조하고 별도 중복을 만들지 않도록 확인해야 합니다.
6. 원자료 PDF와 별도로 만든 가림 열람본을 등록하고, 사건의 **근거 자료와 페이지·문단·증거번호**에 연결합니다. 한 원본을 여러 사건에 연결할 수 있습니다. 원자료를 직접 확인한 뒤 해당 근거 위치 확인을 기록합니다. 설명 분류가 확인된 사실이라면 직접 확인한 원자료가 필요하며, 결정에서 인정한 사실이라면 해당 결정과 판단 범위도 연결해야 합니다.
7. 사건 관리자 화면에서 사건·경과·분류 설명·근거·조문·현재 상태·쟁점을 함께 편집합니다. 정확한 발생일을 모르면 월/연도/기간/확인 중을 선택합니다. 월 단위에는 연도·월만 저장하고 임의 1일을 넣지 않습니다. 검색에 사용하는 월 경계는 임시 계산값이며 발생일로 저장하지 않습니다. 자료 기준일과 상태 확인 기준일을 별도로 입력하고 메모 이후 상고·확정·집행 여부를 추정하지 않습니다.
8. 통합 **헌법/헌법시행규정**을 구분하여 조문 후보를 등록합니다. 공식 총회 원문과 개정 공고, 페이지·개정·시행·확인일을 직접 대조한 뒤 조문 확인 상태를 변경합니다. 조문 자체 확인과 사건 당시 적용은 별개입니다. 공유 조문도 **ArticleCaseLink**에서 연결된 각 사건의 적용 근거·관련성·현재 조문과 차이를 따로 기록해야 합니다. 다른 사건의 적용 상태를 상속하지 않습니다. 검증 전 조문 본문은 교인에게 표시하지 않습니다.
9. 공식 결정은 **Decision**에서 기관·사건번호·결정일·송달일·주문·판단 범위·결과 유형·상소·확정 여부와 원자료/위치를 기록하고 관련 사건들을 연결합니다. 원자료 확인 전에는 알려진 무죄·기각·확정 등으로 표시하지 않습니다. 무죄/불기소/기각/판단 제외는 서로 다른 유형입니다. 모르는 항목은 확인 중으로 남깁니다. 일부 판단을 사건 전체나 모든 행동에 확대하지 않습니다.
10. PDF 가림은 외부의 신뢰할 수 있는 도구로 복구 불가능하게 처리하고 텍스트 추출·복사·레이어·첨부·메타데이터를 수동 검사합니다. 앱은 가림을 자동 수행하지 않습니다. 가림 검증을 하지 않은 PDF와 내부 DOCX는 교인 다운로드를 제공하지 않습니다. 악성 파일 검사와 원본 접근 권한 제한도 운영 절차로 관리하세요.
11. 저장 후 **세 영역 미리보기·게시 점검**을 엽니다. 출처와 분류, 확정 표현, 가림, 자료 기준일, 누락된 조문/결정을 확인합니다. 미검증 설명에 결론 표현이 포함된 경우와 자료 기준일보다 나중에 확보한 문서에 대한 점검 안내를 제공합니다. 내용 수정과 게시 승인을 한 번에 처리하지 않습니다. 작성자·마지막 편집자와 다른 승인자가 확인 후 출처/가림 체크와 승인 사유를 기록하고 게시합니다.

자료·설명·조문·결정 및 연결이 바뀌면 관련 게시 사건은 검토 중으로 되돌아갑니다. 조문 편집 또는 원본 확인 상태 변경도 연결된 사건들의 재검토를 요구합니다. 변경 이력은 제한된 관리자에게만 보관하며 운영 로그의 객체 표시는 내부 ID만 사용합니다.

## 교인 화면과 정정

PC는 사건·근거 자료 / 관련 통합 헌법 / 현재 상황·검토 쟁점을 나란히 표시합니다. 모바일은 이 순서대로 전체 내용을 제공합니다. 목록은 오래된 사건부터 또는 최근 사건부터를 명시하고, 제목·주제·기간 검색과 상태·자료 기준일을 제공합니다. 날짜 미확인 사건은 마지막에 표시됩니다. 비로그인·비활성 교인에게 제목·검색·문서가 노출되지 않으며 파일 요청에서도 세션 권한을 검사합니다.

각 사건의 **비공개 반론·자료 제출·정정 요청**은 해당 사건이 선택된 요청 화면으로 연결합니다. 요청과 처리 답변은 본인과 관리자만 조회합니다. 양측에 같은 접수·검토 기준을 적용하며 미접수는 잘못의 인정이 아닙니다. 승인된 공개 정정 요약만 사건 하단에 표시하고 원본이나 민감한 과거 버전을 자동 공개하지 않습니다.

## 원자료 체크리스트 — 원문 미확보 상태

| 지정된 검토 주제 | 확인해야 할 원자료 |
| --- | --- |
| 공사·건축자금 집행 | 계약·견적·변경 계약·지급 증빙·관련 결의 회의록 |
| 카페 운영·세금 부담 | 운영 약정·수입/비용 기록·세금 고지/신고·부담 주체 자료 |
| 세무대리인 변경 | 위임 계약·변경 통지·의사결정 기록·업무 인계 자료 |
| 당회 공지·임시당회 소집 | 공지 원본·소집 통지·송달/공고 기록·회의록 |
| 사역실행위원회 | 구성·운영 규정·위임 근거·회의록·결정 기록 |
| 제직 임명·회계 선출 | 임명/선출 결의·회의록·적용 규정·표결의 실제 참여 범위 |
| 회계 결재·별도 계좌 | 회계/결재 규정·관리 권한 결의·결재/출납 증빙 |
| 고소·기소·기소장 변경 | 각 사건별 고소장·공소장·변경 신청/허가·송달·해당 판단 원문 |
| 재항고 결정 | 각 사건번호별 결정문 전문·이전 결정·송달·상소/확정 자료 |
| 노회 재판국·후속 절차 | 선고문 전문·주문/이유·번호·송달·상소 접수/확정/집행 자료 |

확인된 실제 조문은 없으며 모든 관련 조문은 공식 원문·개정 자료 확인이 필요합니다. 최근 상태를 추가 확인할 대상은 고소/기소 변경, 각 재항고 절차, 노회 선고와 후속 절차 등이며 메모 기준일 이후의 접수·확정·집행 여부를 추정하지 않습니다. 회의 표결 비율을 전체 교인의 지지율로 취급하지 않습니다.

## 마이그레이션과 검증

`0006`은 기존 필드와 ID를 유지하며 날짜 정확도·기준일·검토 정보, 복수 근거/결정, 사건별 조문 적용, 가져오기 묶음/후보를 추가합니다. `0007`은 기존 Document.case 연결을 새 근거 연결에도 보존하고 위치와 확인 상태를 재확인 대상으로 표시합니다. 기존 날짜를 임의 변경하거나 사건·게시글·문서를 초기화하지 않습니다. 이전 파일 경로도 유지하며 이후 새 업로드만 임의 파일명으로 저장합니다.

검증에는 실제 인물·자료와 무관한 최소 가상 기록만 사용합니다. 원문을 제공받기 전에는 실제 초안 추출이나 자료 검증·게시가 완료됐다고 보고하지 않습니다. 운영 자료는 비공개 DB/파일 저장소로만 관리하며 Git·공개 폴더·테스트 fixture·브라우저 번들·빌드 이미지·운영 로그에 넣지 않습니다.
