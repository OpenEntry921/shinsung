# 교인 전용 고정 사건 본문

## 현재 화면과 데이터 경계

교인 사건 페이지 `/`는 서버의 `MEDIA_ROOT/case-reading.body`에서 검토된 고정 본문을 읽습니다. 사건·조문·결정·출처 문서 테이블을 조회하지 않습니다. 검색 UI와 검색 전용 처리는 제거했으며 옛 검색 URL의 쿼리도 본문을 좁히거나 정렬을 바꾸지 않습니다.

각 사건은 자료 번호·중립 제목 아래 **① 날짜 → ② 사건 경과 → ③ 관련 교단 헌법과 규정 → ④ 쟁점과 추가 확인사항**을 PC·모바일 모두 세로로 표시합니다. 최초 진입에 본문 전체를 표시하며 접기·탭·말줄임·내부 스크롤을 사용하지 않습니다. 발생일의 일·월·연도·기간 정확도와 원문 표현을 보존합니다. 정렬 메타데이터의 0은 미확인 월/일의 표시이며 임의 발생일이 아닙니다. 같은 기간 안의 선후관계는 추정하지 않고, 시작 시점을 정할 수 없는 사건은 별도 영역에 이유와 함께 둡니다.

자료 번호는 열람용 식별자이며 공식 재판 사건번호가 아닙니다. 원문 발췌·역할명 치환 발췌·편집자 요약, 주장·검토 의견·미확인 사항을 구분합니다. 검토 문서의 조항 설명은 공식 원문 미대조로 표시하며 판본·개정·시행·사건 당시 적용 여부를 추정하지 않습니다. 무죄·불기소·판단 제외·확정은 별개이고 이후 진행 상태도 추정하지 않습니다. 내부 전략과 불필요한 개인정보를 옮기지 않습니다.

## 인증과 보호

명부·교인 로그인·세션·관리자 계정·권한·추가 인증은 기존 DB를 사용합니다. 활성 교인 세션 또는 활성 관리자(직원 권한, `portal.view_case`, 유효한 추가 인증)가 있어야 사건 본문과 직접 링크에 접근합니다. 관리자 MFA 또는 사건 조회 권한만으로 교인 게시판 권한을 부여하지 않습니다. 개발용 인증 세션으로 실제 고정 본문을 열 수 없습니다.

본문 데이터의 다운로드/API URL을 만들지 않습니다. 텍스트는 Django 자동 이스케이프를 사용하며 파일 내용에 템플릿이나 HTML 실행 권한을 주지 않습니다. 응답은 `Cache-Control: no-store, private`를 유지합니다. 원문·민감한 과거 버전·관리자 원본을 본문에 포함하지 않습니다.

## 공개 저장소에서의 비공개 본문 보관

GitHub 저장소가 공개이므로 실제 열람 본문도 커밋하지 않습니다. 코드와 일반 안내·가상 테스트만 PR에 포함합니다. 본문은 체크아웃 밖 기존 비공개 자료 경로에 보관합니다. 저장소 안·심볼릭 링크·잘못된 형식의 파일은 거부합니다. 실제 원문 DOCX, 편집 등록 JSON, DB 백업·명부·비밀키 및 `case-reading.body`는 Git·정적 폴더·브라우저 번들·배포 빌드 입력에 넣지 않습니다.

본문 파일은 JSON 형식의 **별도 서버용 편집 본문**이며 DB 등록용 `initial.review.json`과 다릅니다. DB 등록 명령·`seed_demo`·컨테이너 시작 시 가져오기는 필요하지 않습니다. 원문 `source.docx`와 기존 편집 산출물 `initial.review.json`을 대조하고 필요한 범위만 검토하여 만들며, 이 입력 파일들은 공개하지 않습니다. 기존 등록 명령과 DB 관리자 기능은 보존되지만 해당 DB 자료를 수정해도 새 열람 페이지 본문은 변경되지 않습니다.

파일의 최상위 필드는 `version: 1`, `reviewed: true`, `basis_on`, `source_title`, `source_filename`, `entries`입니다. 각 사건에는 안정적인 `key`, `title`, 표시용 `date_label`, 정렬용 `order: [연, 월 또는 0, 일 또는 0]` 또는 `null`, `ordering_note`, `source`, `overview`, `issues`, `needed`, `responses`, `statements`, `rules`, 선택적인 `legacy_ids`를 둡니다. 출처에는 원문 제목·절·표 행/문단 위치를 기록합니다. `statements`는 `kind`(unknown/claim/opinion), `presentation`(summary/quotation/redacted_quotation), `text`, `source`이며, `rules`는 `citation`, `description`, `source`, `relevance`입니다. 이 경로는 원자료 대조 완료나 공식 판단을 생성하지 않습니다.

`/cases/material/<자료번호>/`는 인증 확인 후 `/#material-<자료번호>`로 이동합니다. 기존 숫자 링크 `/cases/<ID>/`는 본문에 명시적으로 대조한 `legacy_ids`만 연결합니다. 운영 DB의 실제 ID와 별도로 대조해야 하며, 로컬 ID가 운영과 같다고 가정하지 않습니다. 대응이 확인되지 않은 ID는 404로 종료하고 다른 사건을 추정해서 연결하지 않습니다. 게시글·문서의 DB 연결은 삭제하거나 변경하지 않습니다.

## 검토 변경·머지·배포와 운영 후속 작업

이번 작업은 PR과 로컬 검증까지이며 Cloudtype 운영 변경·등록·이전·배포를 수행하지 않습니다. 공개 저장소에서는 본문을 머지에 포함할 수 없으므로 **PR 머지만으로 실제 본문이 운영에 생기지 않습니다.** 운영 전 검토한 본문을 별도로 비공개 전달·배치해야 합니다. GitHub를 통한 코드 검토/머지/배포와 본문의 비공개 검토·승인·버전 관리/배치를 하나의 변경 절차로 기록합니다. 자동 동기화나 강제 덮어쓰기는 하지 않습니다. 실제 본문도 코드와 함께 머지하여 배포하려면 먼저 저장소 및 배포 산출물의 접근을 비공개로 전환·검증하는 별도 작업이 필요합니다.

운영 담당자가 기존 설정을 확인할 때는 실제 서비스의 동일 환경과 `manage.py` 디렉터리에서 다음을 실행합니다. 설정·경로는 임의로 바꾸지 않습니다.

```sh
python manage.py shell -c "from django.conf import settings; print(settings.DATABASES['default']['ENGINE']); print(settings.DATA_DIR); print(settings.MEDIA_ROOT)"
```

현재 인증 DB는 SQLite `DATA_DIR/portal.sqlite3`, 비공개 자료는 `MEDIA_ROOT=DATA_DIR/private`입니다. 기본값은 체크아웃의 `runtime`입니다. Cloudtype의 실제 DATA_DIR·볼륨 마운트·파일 권한은 이번에 확인하지 않았습니다. 파일만으로 사건을 읽는다고 교인 명부·관리자·세션 DB의 영구 보존이 해결되지 않습니다. 운영 전 인증 DB와 비공개 본문의 영구 볼륨, UID 10001 읽기 권한, 백업·복구·재시작/재배포 후 보존, HTTPS·실제 SMS·관리자 추가 인증을 각각 확인해야 합니다. 기존 DB를 지우거나 새로운 경로로 연결하지 않습니다.

쓰기 중지 및 변경 전 백업 후, 검토된 본문을 실제 MEDIA_ROOT의 `case-reading.body`로 제한 접근 방식으로 배치합니다. 폴더 700·파일 600과 실제 서비스 UID 읽기 권한을 확인하고, 원자적인 파일 교체 및 비공개 이전 버전 보관으로 복구할 수 있게 합니다. 기존 원문·명부·자료는 건드리지 않습니다. 실제 교인 인증으로 본문과 직접 링크를 확인하고 로그아웃·비활성 계정 및 정적 경로 노출 차단도 확인합니다. 원자료 미대조 표시와 날짜 표현, 실제 운영 ID 별칭을 확인한 다음 재시작 후 파일과 인증 DB가 남는지 검증합니다.

본문 미배치는 관리자 문의 안내, 파일 검증 실패는 개인정보 없는 503 안내로 처리합니다. 이 상태를 실제 자료 표시 완료라고 보고하지 않습니다. 기존 사건 테이블과 자료는 보존하며 삭제는 별도 후속 작업입니다. 반론·정정 접수와 DB 관리자 화면의 기존 기능은 유지하고, 고정 본문에 관한 요청은 자료 번호를 요청 본문에 기재하도록 안내합니다.
