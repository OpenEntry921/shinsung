# 인증된 사건 HTML 본문

사건 열람은 `portal/templates/portal/direct_case_reading.html`의 실제 발췌 본문을 Django 서버에서 렌더링합니다. 사건·조문·문서 DB, JSON, MEDIA_ROOT의 본문 파일, 외부 API와 별도 디스크가 본문 표시 조건이 아닙니다. 교인 인증 DB와 기존 관리자·게시글 기능은 유지합니다.

원문은 이번 첨부 `church_dispute_strategy_memo.docx`이며 기준일은 2026-09-19입니다. 제1절 연표의 30건과 제2절 판결 요지·제3/4절의 관련 설명을 발췌했습니다. 내부 대응 전략·목표·로드맵은 제외하고 불필요한 인명은 역할명으로 편집했습니다. 모든 설명은 검토 문서의 기재이며 공식 판결문·조문 원자료 대조 완료로 표시하지 않습니다. 제목과 연결 설명은 편집자가 정리했습니다.

각 사건은 날짜 → 사건 내용 → 관련 헌법 조문 → 판결 설명 및 우리의 의견 순서로 PC·모바일 모두 세로 표시됩니다. 날짜 기간이 다른 사건과 겹치는 E06/E10/E22는 별도 묶음에서 원래 날짜와 순서를 확정하지 못하는 이유를 표시합니다. 나머지 항목은 연표 순서대로 읽습니다. E30의 9월 1일 변론종결과 9월 11일 선고를 구분합니다. 회의 표결은 전체 교인 지지율로 환산하지 않습니다.

활성 교인 세션 또는 추가 인증을 마친 권한 있는 관리자가 필요합니다. 활성 명부의 이름·전화번호가 일치하면 교인 세션을 만들고 바로 본문을 표시합니다. SMS·인증번호·환경 모드에 따른 별도 사건 차단은 사용하지 않습니다. 운영 환경변수나 인증 DB를 이번 작업에서 변경하지 않습니다. 교인 명부와 HTTPS·세션 설정은 운영자가 별도로 확인해야 합니다. 응답은 `no-store, private`이며 본문은 공개 static·API·다운로드로 제공하지 않습니다. 기존 `/cases/material/E01/` 및 열람용 번호 1~30의 직접 경로는 같은 사건 앵커로 이동합니다.

실제 본문 템플릿은 교인 전용 자료입니다. 공개 저장소에 푸시하지 않습니다. 공개 여부를 확인하고 비공개 저장소에서만 코드 리뷰·머지·사용자 배포 절차로 본문을 반영합니다. DOCX·DB·교인 명부·비밀값은 커밋하지 않습니다. 공개 상태에서 작업할 때는 로컬 본문 템플릿을 `.git/info/exclude`로 제외해 실수로 올리지 않습니다. 이번 제출은 저장소 비공개 전환을 직접 확인한 후 실제 템플릿을 포함합니다. 이후 저장소를 공개로 전환하면 소스와 Git 이력의 본문도 노출될 수 있으므로 공개 전환을 하지 않습니다. PR #10의 PostgreSQL 방향과 운영 이관은 이 작업에 적용하지 않습니다.

본문 수정은 원문을 직접 읽고 해당 템플릿의 문단·출처·의견 분류를 함께 수정하는 방식입니다. 사건 DB 등록·가져오기·외부 본문 복원은 필요하지 않습니다. 기존 사건 테이블·ID·문서·게시글 연결을 삭제하지 않습니다. 교인 로그인 DB의 영구 보존은 별도 운영 과제로 남습니다.

## 이름·전화번호 로그인으로 변경

최초 구현 커밋 `08a0586`부터 일반 로그인은 SMS 요청과 `/otp/` 확인에 의존했습니다. 이름·전화번호를 제출하는 단계만으로 세션을 만드는 코드는 없었습니다. 실제 SMS 설정이 없으면 운영 모드에서 인증 가능한 challenge가 만들어지지 않았습니다. PR #11의 HTML 본문 변경은 개발 세션의 사건 접근을 별도로 차단했고, PR #12는 이 흐름의 재인증·로그인 화면 연결을 제안했으나 아직 머지되지 않았습니다.

이번 요구에 따라 `/login/`에서 활성 명부의 정확한 이름과 정규화된 전화번호를 서버가 조회하여 기존 교인 UUID로 로그인합니다. 전화번호가 여러 활성 기록에서 공용으로 쓰이면 일반 로그인을 허용하지 않고 기존 관리자 신원 확인·개인용 일회성 접속 절차를 유지합니다. 없는 기록을 생성하지 않습니다. 작성자 실명과 ID는 기존 세션·명부에서 적용합니다. SMS 재발송용 1분 대기는 제거하고 IP·전화번호별 입력 시도 제한, CSRF, 세션 만료, 로그아웃, 비활성화·전화번호 변경에 따른 세션 무효화와 관리자 추가 인증을 유지합니다.

SMS 설정·발송·인증번호 입력은 필요하지 않으며 개발 모드도 이름·전화번호 로그인 후 같은 HTML을 표시합니다. 로그인 화면의 오래된 인증번호 폼은 제거합니다. `/otp/` 주소는 로그인 화면으로 돌려보내며 이전 SMS·개발 OTP로 새 세션을 만들지 않습니다. 기존 SMS 세션은 이름·전화번호로 다시 로그인해야 합니다.

이 방법은 등록 정보 일치 확인이며 휴대전화 소유·개인 신원을 별도로 증명하지 않습니다. 이름과 전화번호를 아는 사람이 해당 명부 기록으로 로그인할 위험이 있습니다. 공개된 가상 계정의 정보도 이 방식의 로그인 정보가 되므로 실제 자료 접근을 제한할 비밀 자격증명으로 취급해서는 안 됩니다. 회원가입·공용 비밀번호·새 외부 인증 서비스는 추가하지 않습니다. 관리자 비밀번호·개인별 TOTP는 변경하지 않습니다.

이번 변경에서 교인 DB·HTML 본문·게시글·문서·ID를 삭제·재생성·이관하지 않고 Cloudtype 환경변수·서비스도 변경하지 않습니다. 실제 본문 파일은 기존 서버 템플릿 그대로입니다. 운영 모드의 HTTPS·보안 쿠키·로그인 DB 보존은 여전히 별도 운영 확인이 필요합니다.
