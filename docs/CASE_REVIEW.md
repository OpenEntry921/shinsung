# 인증된 사건 HTML 본문

사건 열람은 `portal/templates/portal/direct_case_reading.html`의 실제 발췌 본문을 Django 서버에서 렌더링합니다. 사건·조문·문서 DB, JSON, MEDIA_ROOT의 본문 파일, 외부 API와 별도 디스크가 본문 표시 조건이 아닙니다. 교인 인증 DB와 기존 관리자·게시글 기능은 유지합니다.

원문은 이번 첨부 `church_dispute_strategy_memo.docx`이며 기준일은 2026-09-19입니다. 제1절 연표의 30건과 제2절 판결 요지·제3/4절의 관련 설명을 발췌했습니다. 내부 대응 전략·목표·로드맵은 제외하고 불필요한 인명은 역할명으로 편집했습니다. 모든 설명은 검토 문서의 기재이며 공식 판결문·조문 원자료 대조 완료로 표시하지 않습니다. 제목과 연결 설명은 편집자가 정리했습니다.

각 사건은 날짜 → 사건 내용 → 관련 헌법 조문 → 판결 설명 및 우리의 의견 순서로 PC·모바일 모두 세로 표시됩니다. 날짜 기간이 다른 사건과 겹치는 E06/E10/E22는 별도 묶음에서 원래 날짜와 순서를 확정하지 못하는 이유를 표시합니다. 나머지 항목은 연표 순서대로 읽습니다. E30의 9월 1일 변론종결과 9월 11일 선고를 구분합니다. 회의 표결은 전체 교인 지지율로 환산하지 않습니다.

활성 교인 세션 또는 추가 인증을 마친 권한 있는 관리자가 필요합니다. 개발 OTP로 실제 본문을 열지 못하게 유지합니다. 운영 환경변수나 인증 DB를 이번 작업에서 변경하지 않습니다. 정상 운영 인증 설정은 운영자가 별도로 확인해야 합니다. 응답은 `no-store, private`이며 본문은 공개 static·API·다운로드로 제공하지 않습니다. 기존 `/cases/material/E01/` 및 열람용 번호 1~30의 직접 경로는 같은 사건 앵커로 이동합니다.

실제 본문 템플릿은 교인 전용 자료입니다. 공개 저장소에 푸시하지 않습니다. 공개 여부를 확인하고 비공개 저장소에서만 코드 리뷰·머지·사용자 배포 절차로 본문을 반영합니다. DOCX·DB·교인 명부·비밀값은 커밋하지 않습니다. 공개 상태에서 작업할 때는 로컬 본문 템플릿을 `.git/info/exclude`로 제외해 실수로 올리지 않습니다. 이번 제출은 저장소 비공개 전환을 직접 확인한 후 실제 템플릿을 포함합니다. 이후 저장소를 공개로 전환하면 소스와 Git 이력의 본문도 노출될 수 있으므로 공개 전환을 하지 않습니다. PR #10의 PostgreSQL 방향과 운영 이관은 이 작업에 적용하지 않습니다.

본문 수정은 원문을 직접 읽고 해당 템플릿의 문단·출처·의견 분류를 함께 수정하는 방식입니다. 사건 DB 등록·가져오기·외부 본문 복원은 필요하지 않습니다. 기존 사건 테이블·ID·문서·게시글 연결을 삭제하지 않습니다. 교인 로그인 DB의 영구 보존은 별도 운영 과제로 남습니다.

## 첫 화면이 운영 인증 안내만 보이는 경우

이전 코드의 문구는 `APP_MODE=development`이면서 유효한 교인 또는 추가 인증 관리자 세션이 사건 경로에 들어왔을 때 출력됐습니다. 로그인 후 `/`로 이동해 이 조건에 걸리면 본문 대신 403 문장만 보였습니다. 수정 후에는 개발 세션을 로그아웃시키고 기존 로그인 화면으로 이동합니다. 로그인 화면에는 실제 자료를 시연 환경에서 열 수 없다는 안내와 기존 이름·전화번호·인증번호 입력이 함께 표시됩니다.

정상 운영에서는 기존 명부 일치 확인→실제 SMS→일회성 인증번호 확인→HTML 본문 순서를 유지합니다. 개발 OTP를 운영 인증으로 인정하지 않습니다. 새 세션과 OTP는 발급 환경에 연결되어 모드가 바뀌면 재인증이 필요합니다. 수정 전 세션·OTP도 다시 인증해야 합니다. 교인·게시글·ID·관리자 계정을 초기화하지 않으며 새 DB나 자료 등록을 요구하지 않습니다.

Cloudtype의 실제 설정을 확인할 때는 터미널에서 아래처럼 값의 존재 여부만 출력합니다. SMS 키·비밀키·명부를 출력하지 않습니다. `sms_config_present`는 발송 성공 확인이 아닙니다.

```sh
python manage.py shell -c "from django.conf import settings; print({'APP_MODE': settings.APP_MODE, 'DEV': settings.DEV, 'sms_config_present': all((settings.SMS_API_KEY, settings.SMS_API_SECRET, settings.SMS_SENDER))})"
```

실제 사건 열람은 `APP_MODE=production`과 기존 실제 SMS 또는 관리자 추가 인증이 필요합니다. 개발 설정에서는 로그인 화면으로 이동하도록 개선되어도 실제 본문은 제공하지 않습니다. 운영자는 기존 DB를 그대로 유지한 채 운영 인증 설정과 실제 발송을 확인해야 합니다. 이 코드 수정 과정에서 Cloudtype 환경변수·DB·비밀키·배포·재시작은 변경하지 않습니다. Dockerfile은 기존 서버 템플릿을 COPY하므로 별도 본문 파일 배치가 필요하지 않습니다.
