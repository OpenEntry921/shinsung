# 사건 자료 등록·검토·게시

## 교인 열람 화면

검색창 아래에서 **① 사건 경과 → ② 관련 교단 헌법과 규정 → ③ 쟁점과 추가 확인사항**을 PC·모바일 모두 세로로 제공합니다. 최초 진입은 검색 없이 게시된 자료 전체를 읽습니다. 제목·본문·발췌·날짜·조항 번호·쟁점 검색은 연결된 사건·규정·검토 내용을 함께 좁히며 초기화하면 전체로 돌아갑니다. 영역 내부 스크롤·말줄임·펼치기·탭은 사용하지 않습니다. 직접 사건 링크는 유지합니다.

발생일의 일·월·연도·기간 정확도를 보존합니다. 검색용 월 경계는 임시 계산값이고 실제 발생일에 임의 1일을 넣지 않습니다. 자료 번호는 가져오기 식별자이며 재판기관의 공식 사건번호가 아닙니다. 문서 기준일 이후 진행·상소·확정·집행 여부는 별도로 확인합니다.

게시 상태와 원자료 검증 수준은 별개입니다. 검토 문서의 설명은 출처·원자료 미대조·의견 표시와 개인정보 검토를 거쳐 게시할 수 있습니다. 공식 조문 미확인을 이유로 검토 문서의 조항 설명까지 숨기지 않지만, 공식 조문 본문은 기존 원문·개정·판본 검증 조건을 충족해야 표시합니다. 무죄·불기소·판단 제외·확정은 서로 구분하고 문서에서 묶어 설명한 항목의 개별 결론을 추정하지 않습니다. 표결 기록은 교인 지지율이 아닙니다.

## 비공개 원문과 편집 등록 파일

원본 DOCX와 편집 등록 JSON은 저장소·정적 파일·브라우저 번들·이미지에 넣지 않습니다. 원본은 `Document.internal_memo=True`, 초안·관리자 전용으로 보존하며 교인 다운로드가 금지됩니다. 교인에게는 역할명으로 정리한 발췌, 편집자 요약, 검토 문서의 의견을 구분하여 보여줍니다. 등록 파일(`*.review.json`)은 비공개 경로에 별도로 전달합니다. 앱은 원문 문장을 자동으로 사실로 승격하거나 법적 결과를 판정하지 않습니다.

`register_reviewed_materials`는 원문을 DOCX 안전 파서로 읽고, 검토 파일의 원문 SHA256와 문단/표 행 위치를 대조합니다. `bN`은 DOCX 본문의 N번째 블록, `bN:rM`은 해당 표의 M번째 행(헤더 포함)입니다. 허용된 경과·판결 요지·구조 진단·쟁점·미확인 절 이외의 위치는 거부합니다. 등록 파일은 작업자가 원문을 직접 대조하고 전략·개인정보를 제외하여 작성하는 별도 편집 산출물입니다. `reviewed=true`나 정규식 검사는 실제 편집 검토를 대신하지 않습니다. 주소·서명·계좌·상담 내용도 수동 점검합니다.

등록 파일에는 자료 묶음 `key`, `source_sha256`, `source_filename`, `source_title`, `basis_on`, `reviewed`, `cases`, `rules`가 있습니다. 사건마다 안정적인 `key`, 중립 제목·주제·날짜 정확도·설명·출처 위치·분류된 `statements`를 기록합니다. 조항 설명은 사건의 `case_keys`에 연결합니다. 원문 인용은 실제 해당 위치와 일치해야 하며 역할명 치환 발췌는 그 형식을 명시합니다. 확인된 사실을 만드는 분류는 이 메모 등록 경로에서 허용하지 않습니다.

## 전용 등록 명령

실제 자료 적용은 `APP_MODE=production`, 체크아웃 밖 비공개 `DATA_DIR`, `MEDIA_ROOT=DATA_DIR/private`, `PRIVATE_STORAGE_CONFIRMED=true`, `REAL_MATERIALS_ENABLED=true`에서만 가능합니다. 개발 `seed_demo`는 가상 교인만 만들며 실제 사건을 등록하지 않습니다. 실제 등록 묶음이 있는 DB를 시연 모드로 잘못 연결하면 개발용 인증 세션으로 보호 자료를 읽지 못하도록 차단합니다. 전용 명령은 웹 요청이 아닌 서버 운영자의 오프라인 준비에도 사용합니다. 실제 SMS가 없으면 웹 로그인은 계속 실패하며, 오프라인 등록 또는 로컬 검증용 세션이 실제 SMS 인증 성공을 뜻하지 않습니다. 웹 관리자 업로드·자동 후보 추출은 기존 운영 인증 조건을 유지합니다.

작성자와 검토자는 서로 다른 기존 활성 관리자 계정입니다. 작성자에게 `portal.add_case`, 게시 승인자에게 `portal.publish_case` 권한이 필요합니다. 명령은 계정·권한·명부를 자동 생성하지 않습니다.

```sh
# 미리보기: 원문/등록 파일 검사와 생성·보존 예정 수량. DB/파일 변경 없음.
python manage.py register_reviewed_materials /data/import-private/source.docx \
  --plan /data/import-private/initial.review.json \
  --author '내용편집자계정' --reviewer '게시승인자계정'

# 사용자 요청에 따라 편집·출처·개인정보를 검토한 해당 초기 자료만 게시
python manage.py register_reviewed_materials /data/import-private/source.docx \
  --plan /data/import-private/initial.review.json \
  --author '내용편집자계정' --reviewer '게시승인자계정' \
  --apply --publish --approval-reason '초기 발췌·출처·역할명·검증 수준을 검토함. 원자료 미대조.'
```

`--apply` 없이 수량만 확인합니다. `--apply`만 사용하면 초안으로 등록하고 관리자에서 검토·게시할 수 있습니다. `--publish`는 생성되는 해당 묶음만 게시하며 다른 초안은 건드리지 않습니다. 원자료 검증 표시를 만들거나 전체 승인 기능을 해제하지 않습니다. 생성 전체는 DB 트랜잭션으로 처리하고 실패하면 DB 반영을 취소하며 새 원본 파일도 제거합니다.

원문 SHA256에도 고유 제약을 적용하므로 다른 식별자로 같은 원문을 중복 등록할 수 없습니다. 같은 묶음과 같은 파일을 반복 실행하면 기존 사건 ID·연결·관리자 편집·게시 철회 상태를 그대로 보존합니다. 이미 등록된 사건을 자동 재게시하지 않습니다. 같은 식별자의 원문/편집 파일이 변경되면 거부하며, 수정은 기존 관리자 편집·재검토·승인 경로를 사용합니다. 새 식별자를 임의로 주어 같은 자료를 중복 등록하지 않습니다.

## Cloudtype 반영과 보존 확인

코드만 재배포해도 로컬 DB와 자료는 이전되지 않습니다. 현재 코드의 DB는 SQLite(`DATA_DIR/portal.sqlite3`)이며 외부 DB 접속 환경변수를 임의 추가하지 않습니다. 실제 배포 서비스의 **같은 컨테이너/환경변수**, `manage.py` 디렉터리에서 확인합니다.

```sh
python manage.py shell -c "from django.conf import settings; print(settings.DATABASES['default']['ENGINE']); print(settings.DATA_DIR)"
python manage.py case_data_status
```

Cloudtype 설정 화면에서 해당 경로의 실제 영구 볼륨 마운트·UID 10001 권한을 확인합니다. 설정 플래그만으로 영속성이 검증되지는 않습니다. 기존 운영 DB가 다른 경로에 있으면 백업·이전 계획 없이 `DATA_DIR`를 바꾸지 않습니다. 새 빈 DB로 연결되어 자료가 없는 것처럼 보일 수 있습니다.

운영 쓰기를 중지하고 동일 볼륨에 접근하는 관리 환경에서 변경 전 백업을 만듭니다. 백업에는 민감한 원본이 있으므로 제한 접근·암호화된 외부 보관과 복원 검증이 필요합니다.

```sh
python manage.py backup_private /secure-backups/new-pre-import-snapshot
python manage.py migrate --noinput
python manage.py bootstrap_roles
```

원문과 검토 파일을 HTTPS 등 비공개 전송으로 `/data/import-private`에 넣고 디렉터리 700, 파일 600 권한을 적용합니다. 위 미리보기 → 해당 초기 자료 적용 명령을 실행합니다. 준비된 검토 파일을 사용하므로 사건을 하나씩 재입력할 필요가 없습니다. 이 입력 파일을 Git에 올리거나 시작 스크립트에서 매번 실행하지 않습니다.

그 뒤 `case_data_status`의 `counts.cases`, `articles`, `reviewed_imports`, `registered_cases`, `case_states.published`를 확인하고 실제 교인 인증으로 최초 본문·출처·세 영역·검색·초기화를 확인합니다. 등록 명령 재실행은 생성 0건·기존 자료 보존이어야 합니다. 재시작과 재배포 후 같은 수량·ID·실제 본문·비공개 원본을 다시 확인합니다. Cloudtype 연결 없이 이 검증을 완료했다고 보고하지 않습니다.

## 기존 관리자 작성·검토·정정

새 자료는 관리자 Document 화면에서 출처·확보일·작성일·송달일·결정일·발췌 범위를 기록합니다. 일반 PDF는 원본과 열람본을 분리하고, 복구 불가능한 가림을 외부 도구로 수행하여 텍스트·레이어·첨부·메타데이터 검사를 완료한 열람본만 승인합니다. 앱이 자동 가림 또는 악성 파일 검사를 보증하지 않습니다.

내부 메모 자동 후보 추출은 `/materials/import/`에서 원문·후보·중립 요약을 검토하고 초안으로 전환하는 기존 흐름을 유지합니다. 자료·설명·조문·결정·연결을 변경하면 관련 사건은 재검토됩니다. 등록 원본의 변경도 연결된 사건을 재검토로 되돌리며, 게시 전 원문 체크섬을 확인하여 출처가 다른 파일로 바뀐 상태에서 승인되지 않게 합니다. 작성자·마지막 편집자와 다른 승인자가 세 영역 미리보기, 출처·확정 표현·개인정보 가림을 확인하고 승인 사유를 남깁니다.

사건별 비공개 반론·자료 제출·정정 요청은 본인과 관리자만 봅니다. 양측에 같은 기준을 적용하며 답변 미접수는 잘못의 인정이 아닙니다. 공개 정정 요약만 보여주고 원본·민감한 과거 버전은 자동 공개하지 않습니다. 페이지·직접 링크·API·문서마다 기존 활성 교인/관리자 권한 검사를 유지합니다.

## 마이그레이션과 검증

`0006`·`0007`의 기존 사건·문서 연결에 더해 `0008`은 검토 문서의 조항 설명·출처, 발췌/요약 표현 형식과 안정적인 묶음/사건 연결을 추가합니다. `0009`는 등록 원문 해시의 고유 제약을 추가합니다. 기존 ID·게시글·파일을 삭제·초기화하지 않습니다. 공식 조문 검증과 사건 당시 적용 상태는 그대로 분리합니다.

자동 테스트는 실존 인물·자료와 무관한 최소 가상 문서만 사용합니다. 실제 발췌 파일·DB·원본·화면 캡처는 저장소와 배포 이미지에 포함하지 않습니다. 로컬 실제 자료 표시, 가상 자동 테스트, 실제 SMS/Cloudtype 배포·영속성 검증의 결과를 각각 구분합니다.
