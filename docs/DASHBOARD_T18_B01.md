## 공동상황판

기존 ProgressRecord·관리자·다섯 구역을 유지합니다. `portal/dashboard.py`의 버전 관리된 기본14개 항목을 조회 때만 보충하며 DB에 저장·동기화하지 않습니다. 새로고침·재배포·재실행으로 레코드가 늘거나 운영 기록이 덮어써지지 않습니다.

운영자의 published=True 기록을 기준일/수정일 순으로 먼저 표시합니다. 같은 구역에서 기본 항목의 주 연결 사건을 지정하거나 정확한 기본 제목으로 게시하면 해당 기본 항목 대신 운영 글을 보여줍니다. 다른 운영 기록은 기본 항목과 함께 표시합니다. 이번 주 안내에서 사건 키가 없는 운영 공지를 게시하면 기본 모임 안건보다 우선합니다. 비게시 기록은 표시하지 않습니다. T키와 기존 E키 운영 기록의 직접 링크도 유지합니다.

분류 문구로 자료에 기재된 기록·우리의 검토 쟁점·앞으로 할 일(질의안/검토 안건)·확인되지 않은 진행을 구분합니다. 사실 판정이나 자동 발송을 수행하지 않습니다. 각 항목에는 설명·상태·자료 기준일·관련 사건과 가능한 가림 사본 링크를 제공합니다. S01은 공개 사본 미포함 안내만 있고 가짜 버튼이 없습니다.

청구·환급·회신 거부·탄원 접수를 혼동하지 않으며 요청안은 ‘질의안·검토 중 (미전달)’입니다. 수신 주체·전달일·답변 요청일을 만들지 않았습니다. 기존 전달 완료의 실제 수신 주체/전달일 검증은 그대로입니다. 토요일7시라는 기존 안내의 최신 날짜·장소를 확인하지 못해 ‘다음 모임 검토 안건’으로만 표시합니다.

기본 자료 기준일은 해당 청구문서 날짜(10/28·10/30) 또는 마지막 정리본 기준일(11/4)입니다. 화면 편집일11/6을 별도로 표시하며 사건 발생일·자료 확인일로 바꾸지 않았습니다. 실제 운영 DB의 최신 게시 기록·회의 공지와 Cloudtype 접속은 직접 확인하지 않았습니다. 운영 기록 우선/보존은 격리 가상 기록으로 검증했습니다.

## B01 실물 확인·복구

- 현재 main의 B01.pdf를 직접 렌더링해 PDF2쪽의 지정 주소 행이 가려져 있음을 확인했습니다. 해당 페이지의 단일 내부 래스터 이미지를 추출해도 주소 행은 제거된 상태였고, 복사 가능한 페이지 텍스트는0자였습니다. 원본·주소 값을 복원하거나 로그에 전사하지 않았습니다. PDF 전체 개인정보 가림의 완전성을 새로 보증하는 의미는 아닙니다.
- 실제 크기5203412바이트, 실제26쪽을 계산해 연결표의 B01 bytes만5156639→5203412로 정정했습니다. 파일명·제목·쪽수·다른 자료 항목은 그대로이며 PDF 바이트도 변경하지 않았습니다. 기존 크기/형식/승인 목록 검증을 완화하지 않았습니다.
- `verify_case_documents`는 실제28개(PDF27/489쪽+JPEG1장)와156개 사건 인용 검증에 성공합니다.
- T18의 A01 PDF6쪽·B01 PDF10~16쪽·A12 PDF15~16쪽 표기는 그대로입니다. 실제 manifest resolver의 B01 URL 뒤에 #page=10이 붙습니다. T28의 B01은 #page=7로 유지하며 일괄10쪽 변경이나 과거 해시 URL 하드코딩을 하지 않았습니다.
- DEBUG=False 실제 WhiteNoise/Gunicorn의 현재 B01 GET200·application/pdf·길이·전체 SHA-256 일치를 확인했습니다. PC/모바일에서 실제 새 탭 URL의 #page=10을 확인했습니다. PDF뷰어별 페이지 fragment 동작에는 차이가 있을 수 있습니다.

## 이전 가림 전 수집본 URL

로컬 STATIC_ROOT에 이전 해시 B01 파일이 남아 있었고 실제 HEAD200으로 제공되는 것을 확인했습니다. `collectstatic --clear --noinput` 후 프로세스를 다시 시작하자 이전 URL은404, 현재 수정본은 정상 PDF와 일치했습니다. 테스트용 가상 PDF로 이 검사를 대신하지 않았습니다.

`scripts/start-production.sh`의 기존 collectstatic 단계에 **--clear**를 추가했습니다. 역할 초기화·마이그레이션·개발 시드 조건·Gunicorn 순서와8000포트는 유지합니다. 정리 대상은 재생성 가능한 STATIC_ROOT뿐이며 소스 static·DB·MEDIA_ROOT·비공개 원본을 삭제하지 않습니다. 이미지의 runtime 폴더는 기존 .dockerignore에서도 제외됩니다. Git 기록 삭제·강제 푸시는 하지 않습니다.

현재 Cloudtype에서 이전 URL이 계속 열리는지, CDN/브라우저 캐시가 남는지는 **미확인**입니다. 로컬404를 운영 서버 정리 완료로 보고하지 않습니다. 사용자가 검토·병합·기존 배포를 진행하면 Gunicorn 시작 전에 정적 폴더가 재생성됩니다. 이후 예전에 제공한 B01 해시 URL이404인지와 현재 화면의 URL이 수정본인지 확인해야 합니다. 이미 내려받거나 캐시된 사본까지 이 코드로 회수할 수는 없습니다. 별도 캐시가 설정돼 있다면 해당 설정·무효화 방법은 실제 운영 환경에서 확인해야 합니다.
