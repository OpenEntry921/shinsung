# 준비위원 검토실

현재 첫 화면은 상고 주장별 준비표입니다. 기존 72개 점검표는 `/prepare/events/`에서 유지합니다. 원문 범위·새 의견 모델·보호 열람본·검증은 [상고 준비실 안내](APPEAL_PREPARATION.md)를 참고하세요.

`/prepare` 또는 `/prepare/`에서 접속한다. 기존 메뉴·메인·푸터에는 링크를 추가하지 않는다.

현재 요청에 따른 임시 공용 접속 정보는 이름 `준비위원`, 전화번호 `01011111111`이다. 전화번호의 하이픈·공백은 정규화한다. SMS나 교인명부 연동 없이 준비 페이지에만 별도 1시간 세션을 발급한다. 기존 교인 로그인과 접근 조건은 바꾸지 않는다. 이 정보는 신원 확인 수단이 아니며, 전달받은 사람도 같은 권한으로 접속할 수 있다. 개별 준비위원 승인 방식은 후속 작업이다.

## 자료와 검토 범위

- main `66305c2522a82a053480daf33bcbedc6f5312aa0`의 통합 72개 사건과 기존 ⑤ 우리의 의견을 별도 보존한다. HTML 강조 태그는 평문으로 표시하며 문장과 문단은 유지한다.
- 번호 41번은 T71, 42번은 T41이다. 표시 번호와 고유 키를 각각 저장한다.
- 최초 주장 칸은 기존 웹 경과의 발췌·요약이며, 최초 고소 원문을 새로 읽어 확정한 인용이 아니다. 구별할 수 없는 경우 확인 대기로 표시한다.
- 상고 칸은 `우리측_주장과증거_재검토_20261107.md`의 §2 분석을 재인용한 2차 자료다. PDF를 이번 작업에서 직접 대조한 결과가 아니다. 해당 사건의 상고 대응 관계를 확인하지 않은 항목은 그 상태로 표시한다.
- 위 보고서의 72개 점검 제안은 오류 확정으로 표시하지 않는다. 준비할 자료와 수정·강화 제안은 별도 초안이다.
- `portal/preparation_data.json`은 서버 소스이며 static 경로나 공개 JSON 다운로드 경로를 만들지 않는다.

`scripts/build_preparation_snapshot.py --review <재검토-md-경로> --source-commit <기준-커밋>`으로 재생성할 수 있다. 기존 웹의 원문과 초안을 자동 동기화하거나 덮어쓰지 않는다.

## 의견과 관리

준비위원 의견은 별도 `PreparationComment` 테이블에 저장한다. 작성자 이름은 직접 적는 표기이며 신원 확인된 이름이 아니다. 유형은 사실관계 정정·증거 제공·반박 논리 제안·기타 의견이다. 자료명·쪽수·날짜를 선택적으로 적는다. 기존 사건 댓글·게시판에 나타나지 않는다.

기존 관리자 화면의 **준비위원 검토**에서 사건 고유 키를 입력해 검토 상태·확보 자료·새 초안을 등록한다. 관리자 변경 이력은 기존 Revision/Audit에 남는다. **준비위원 의견**에서는 의견을 숨길 수 있다. 공용 접속으로 다른 사람의 의견을 수정·삭제하거나 기존 원문을 편집하는 기능은 제공하지 않는다.

DB와 세션은 기존 DATA_DIR의 SQLite에 저장하며 기존 백업 범위를 따른다. 재배포 시 DATA_DIR이 영구 저장소로 연결되어 있어야 댓글도 보존된다. 기존 시작 스크립트의 migrate가 신규 테이블을 생성한다. 새 설정값은 필요 없다.

모든 준비 화면에 기존 no-store·noindex 응답 헤더와 CSRF 검사를 적용한다. 로그인·댓글에는 요청 제한을 적용한다. 이름과 전화번호를 로그인 페이지에 미리 표시하지 않는다.
