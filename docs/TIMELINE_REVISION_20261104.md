| 표시 번호 | 저장된 사건 키/URL | 처리 |
| --- | --- | --- |
| 01~40 | T01~T40 | 기존 키 유지 |

## 남은 확인 사항

직접 받은 것은 개정 MD입니다. 원본 PDF27개·회신 이미지1개·S01 DOCX는 이번 작업에서 직접 확인하지 않았습니다. MD 작성자가 서술하는 원자료 대조를 이 구현의 독립 검증으로 승격하지 않습니다. 현재 코드의 자료 ID 매핑은 비어 있어 자료29개는 미연결이며 이름·쪽수/절·행과 미연결 안내만 표시합니다. 가짜 URL·빈 다운로드 버튼을 만들지 않습니다.

새 기사 원문·게시일·작성자·URL, 쌍방 상고 접수·이유·송달과 계류, 변경 허가·본안 판결, 별도 기소장 실물, 배포 기록, 탄원서 최종 인원·제출·접수 등은 개정 MD의 확인 수준을 유지합니다. 준비 사항은 준비 중이며 정리 기준일을 준비 시작일로 바꾸지 않습니다. 14개 보완의 집계·평가·후속 상태는 정리본 기재 수준이지 새 기관 판단이 아닙니다. 날짜·판본 확인 목록과 미확인 자료 목록은 비공개 검토 기록에 원문 그대로 남겼습니다.

## Git 상태와 공개 범위

처음에는 PUBLIC으로 확인되어 업로드를 보류했습니다. 이후 사용자가 Private 전환을 알렸고 공개 웹 조회가 404로 바뀐 상태에서 인증된 Git 조회가 정상 동작하는 것을 확인했습니다. 사용자 요청에 따라 이번 변경만 작업 브랜치에 커밋·업로드하고 PR 제출을 진행합니다. 원문 MD·원자료·회원 DB·명부·비밀값·캡처는 포함하지 않습니다.

기준 커밋은 `8bcdef1`, 작업 브랜치는 `feat/timeline-revision-20261104`입니다. 기존 SMS 브랜치는 포함하지 않습니다. PR의 base는 `main`입니다. 머지·운영 배포·재시작은 하지 않습니다. API 네트워크 제한 등으로 PR 제출이 실패하면 실제 제출 상태를 별도로 보고합니다.

## 데이터 반영·되돌리기

사건 DB 등록·시드·MD 업로드·별도 데이터 이전 명령은 필요 없습니다. 실제 본문 파일을 포함한 코드가 배포돼야 합니다. 기존 시작 스크립트의 `migrate --noinput`이 새 선택 목록/제약을 적용합니다. 운영 DB·비공개 파일의 외부 백업·체크섬·복구 가능성은 운영자가 사전에 확인합니다. 로컬 가상 백업 검증은 운영 백업 완료가 아닙니다.

기존 70개 키는 어느 버전에서도 변경하지 않습니다. 새 T71/T72 글·댓글이 생긴 뒤 구버전 키 제약으로 무조건 역마이그레이션하거나 이를 삭제·재번호화하지 않습니다. 필요하면 코드 표시를 되돌리되 확장 DB 제약과 새 기록을 보존하는 복구 방식을 검토합니다. 백업 이후의 작성 내용을 잃는 무조건 DB 복원도 하지 않습니다. Cloudtype 운영 마이그레이션·재시작·재배포·실제 화면 확인은 미실행입니다.
